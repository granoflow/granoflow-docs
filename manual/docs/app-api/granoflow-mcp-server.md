MCP Server 更适合本机 agent。它把 Granoflow 的能力包装成工具，让 AI 可以在你的授权和本机环境里调用。

## 一个真实场景

如果你在本机使用 Codex、Claude Code 或类似 agent，MCP 比复制粘贴任务列表更稳。

## 怎么判断下一步

| 你遇到的情况 | 先看什么 | 下一步 |
| --- | --- | --- |
| 不知道该从哪里开始 | 当前页面标题和主要入口 | 只选择和当前目标有关的一项 |
| 操作后结果不对 | 状态、空提示、访问记录或同步进度 | 回到上一层，按顺序排查 |
| 担心影响数据 | 备份、同步、账号或权限说明 | 先停下，确认范围后再继续 |

## 边界

先让 Granoflow 桌面端和本地接口可用，再配置 MCP Server。MCP 不是云端同步功能。

更准确地说，MCP Server 是一层薄桥：它把 agent 的请求转发给正在运行的 GranoFlow Local HTTP API。任务、项目、里程碑、回顾和卡片的规则仍然由 GranoFlow app 决定。

这意味着：

- app 没打开，或者本地接口没启用时，MCP 不能凭空读写任务。
- MCP 不应该自己维护另一份任务、节点或卡片状态。
- 涉及删除、发布、账号、同步恢复、密钥或外部服务的操作，仍然需要你明确确认。
- 如果 AI 只是在整理任务描述，它可以先生成预览；真正写入前应让你知道会改哪些字段。

## 和 Connector 的区别

| 项目 | MCP Server | ChatGPT Connector |
| --- | --- | --- |
| 运行位置 | 本机 AI 工具附近 | ChatGPT/网页环境 |
| 适合任务 | 本机 agent 自动化、读写任务 | 对话式查询和整理 |
| 关键前提 | 桌面端、本地接口、工具配置 | Connector 授权和账号环境 |

MCP 的优势是贴近本机工作流。它也因此更需要你理解本机接口、访问码和工具权限。

## 适合让 MCP 做什么

| 场景 | 适合程度 | 原因 |
| --- | --- | --- |
| 列出当前任务、项目或里程碑 | 适合 | 这是本机 app 已经公开的只读信息 |
| 给已完成任务补回顾 | 适合，但要确认内容 | 回顾会长期保留，最好先看预览 |
| 补录历史完成时间 | 适合走专门的历史修正能力 | 普通任务编辑不应随意改历史时间 |
| 批量导入任务或卡片 | 先预览，再确认 | 需要去重、项目复用和写入边界 |
| 处理同步密钥或账号恢复 | 通常不适合自动执行 | 需要用户确认账号、密钥和恢复范围 |
