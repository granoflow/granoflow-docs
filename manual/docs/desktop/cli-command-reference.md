命令参考适合已经知道自己要查什么的人。先确认桌面端正在运行，再复制命令。

## 一个真实场景

如果命令没有返回预期结果，先看访问日志和本地接口状态，不要急着改脚本。

## 先确认接口，再看命令

![命令行工具设置](../../screenshots/zh-cn/route-command-line-tool-settings-command-line-tool-main.png)

命令行工具设置页告诉你本机接口是否可用、地址是什么、访问码在哪里。命令跑不通时，先看这里，而不是先改脚本。

![访问日志](../../screenshots/zh-cn/route-local-http-api-access-log-settings-command-line-tool-access-log-main.png)

访问日志能帮你判断请求有没有到达 Granoflow。如果日志里完全没有记录，问题通常在地址、端口、网络或工具配置；如果有记录但失败，再看权限和参数。

## 怎么判断下一步

| 你遇到的情况 | 先看什么 | 下一步 |
| --- | --- | --- |
| 不知道该从哪里开始 | 当前页面标题和主要入口 | 只选择和当前目标有关的一项 |
| 操作后结果不对 | 状态、空提示、访问记录或同步进度 | 回到上一层，按顺序排查 |
| 担心影响数据 | 备份、同步、账号或权限说明 | 先停下，确认范围后再继续 |

## 边界

命令能跑通的前提是本机服务可用、访问码正确、请求地址指向当前设备。

## 使用前提

```bash
granoflow --help
```

如果命令不可用，先回到桌面端安装和命令行工具设置。命令参考页只负责查用法，不负责替代安装和授权。

| 问题 | 先检查 |
| --- | --- |
| 命令不存在 | CLI 是否安装到 PATH |
| 连接失败 | 桌面端是否运行，本地接口是否开启 |
| 返回未授权 | 访问码是否正确 |
| 数据为空 | 当前账号和本地数据是否符合预期 |

## 下一步

读完这一节后，回到你正在处理的任务，只选一个最小动作继续：记录一条输入、检查一个状态、或打开相关设置完成一次确认。
