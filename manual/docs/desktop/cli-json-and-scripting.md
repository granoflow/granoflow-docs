JSON 输出适合脚本读取，普通文字输出适合人看。写自动化时，尽量让脚本读稳定字段，而不是解析自然语言。

## 一个真实场景

比如你要统计任务数量，就让命令输出 JSON，再由脚本读取 `count` 或列表长度。

## 怎么判断下一步

| 你遇到的情况 | 先看什么 | 下一步 |
| --- | --- | --- |
| 不知道该从哪里开始 | 当前页面标题和主要入口 | 只选择和当前目标有关的一项 |
| 操作后结果不对 | 状态、空提示、访问记录或同步进度 | 回到上一层，按顺序排查 |
| 担心影响数据 | 备份、同步、账号或权限说明 | 先停下，确认范围后再继续 |

## 边界

脚本要把错误路径也写清楚：连接失败、访问码错误、没有数据，应该给出不同提示。

## 下一步

读完这一节后，回到你正在处理的任务，只选一个最小动作继续：记录一条输入、检查一个状态、或打开相关设置完成一次确认。
