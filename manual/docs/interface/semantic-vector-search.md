本地语义搜索不是让你多记一个搜索技巧，而是把“找同一个词”改成“找意思接近的任务、项目、里程碑、卡片和经验”。当你在 Granoflow 里写下很多记录后，真正麻烦的地方常常不是没有资料，而是不记得当时用了哪个词。

向量搜索就是为这个场景准备的。它会在本地把任务、项目、里程碑、卡片、回顾等内容转成一组语义信息。以后你添加卡片、搜索旧记录、导入 AI 生成的卡片，Granoflow 就能先找出意思相近的内容，减少重复整理，也为后续知识图谱能力打基础。

## 一个真实场景

你曾经写过一张卡片：“不要把收集箱当作长期清单。”几周后，你在任务里写的是“临时想法应该什么时候清空”。普通搜索可能更依赖“收集箱”“清单”这些字；启用本地语义搜索后，Granoflow 会尝试把这两段话看成同一类经验，再把相关记录排到前面。

这里的重点不是 AI 替你判断哪张卡片一定正确，而是先把候选范围缩小。最后要关联、跳过还是新建，仍然由你决定。

## 它会出现在哪里

| 使用场景 | 启用后会发生什么 | 关闭后会怎样 |
| --- | --- | --- |
| 任务详情添加卡片 | 直接列出相似卡片，减少手动输入关键词 | 回到关键词或旧的添加流程 |
| 搜索页和卡片管理页 | 优先按语义相近程度排序 | 回到普通文本匹配 |
| AI 导入卡片 | 写入前先展示可能重复或相关的卡片 | 不展示语义预览 |
| 日、周、月复盘 | 推荐和当前复盘内容相近的卡片 | 只保留原有列表和入口 |
| 项目、里程碑、标签候选 | 用语义相近度辅助排序 | 回到原有排序 |

## 模型信息

第一次启用本地语义搜索时，Granoflow 会请你确认下载本地模型。模型不会随安装包预装；如果当前不是 Wi-Fi，下载前会再次确认，并显示需要下载的大小。

| 项目 | 内容 |
| --- | --- |
| 模型 | Google EmbeddingGemma Q8，本地配置 ID 为 `local_google_embeddinggemma_q8` |
| 模型来源 | Google EmbeddingGemma，使用 LiteRT / TFLite artifact，受 Gemma Terms of Use 约束 |
| 模型文件 | `embeddinggemma-300M_seq512_mixed-precision.tflite`，约 179.1 MB |
| Tokenizer 文件 | `sentencepiece.model`，约 4.7 MB |
| 下载和安装占用 | 约 183.8 MB，建议至少预留 300 MB 可用空间 |

::::note[下载后才启用]
Granoflow 只有在模型文件下载完成并通过校验后，才会启用本地向量搜索。校验失败时，模型不会被加载。

向量搜索是很强力的 AI 辅助功能，但不是必装组件。如果某台设备空间紧张，可以先不安装，Granoflow 会继续使用普通搜索和旧流程。
::::

## 存储精度和搜索精度

设置里有两个滑杆，名字相近，但作用不同。先记住一个判断：存储精度决定记录里“保存了多少信息”，搜索精度决定当前设备“读取多少信息来排序”。

| 设置 | 档位 | 作用 |
| --- | --- | --- |
| 存储精度 | 高 / 精细 / 最佳 | 决定每条记录保存多少向量信息。记录只保存到“高”时，把搜索精度调得更高也不会补出不存在的信息。 |
| 搜索精度 | 低 / 中 / 高 / 精细 / 最佳 | 决定当前设备搜索时读取多少向量信息。记录已经用“最佳”保存时，即使用较低搜索精度，仍然能从高存储精度中受益。 |

::::tip[多设备用户的简单做法]
如果你有多台设备，建议至少让一台常用设备保持“最佳”存储精度。它接触到低精度记录时，会在后台把这些记录升级到更高精度，这个过程通常不需要手动处理。
::::

## 模型文件由你管理

已经下载的模型不会因为你尝试别的模型而自动删除。Granoflow 会把删除动作留给你，因为有些用户会下载多个模型比较效果。

| 操作 | 规则 |
| --- | --- |
| 删除已下载模型 | 由你在设置里主动删除 |
| 删除当前正在使用的模型 | 不允许直接删除，避免误删后功能突然不可用 |
| 删除最后一个模型 | 需要先关闭向量搜索，再删除模型 |

## 自动降级

Granoflow 会根据设备性能评估存储精度和搜索精度的默认值与可用上限；你可以在设置里自行调整。如果设备压力较高，Granoflow 可能会把已保存的设置降到更安全的位置。这个降级会写入真实配置，不是只影响当前一次搜索。

如果你一开始使用较高搜索精度很顺畅，后来逐渐被降到较低档，通常不是模型坏了，而是你的记录变多了。同样的搜索精度在更大的数据量上需要处理更多候选内容，占用也会增加；为了避免搜索拖慢设备，Granoflow 会保存一个更稳妥的设置。

发生降级时，你会收到一条内部通知，里面会说明降级前是什么设置、降级后是什么设置。如果你认为设备状态已经恢复，可以再回到设置里手动调高。

## 隐私和同步

向量来自你已经写入 Granoflow 的文本内容。备份、导入、同步和本地接口里，向量字段按文本字段相同的方式处理；不同的是，向量字段不需要像敏感文本那样做脱敏展示。

本地备份首版不主动导出向量。导入或同步后，Granoflow 会根据已有文本重新生成需要的向量。

## 边界

“最佳”表示当前端侧模型的最高本地档位，不等于云端 Gemini 等模型的能力上限。语义排序也不是最终判断：如果你觉得某条卡片不该排在前面，仍然以卡片内容、任务上下文和你的判断为准。

如果你觉得查询卡片的排序经常不正确，可以到 GitHub issue 反馈。我们会根据实际问题考虑用合适方式集成云端向量 API。

## 下一步

启用前，先确认你是否真的需要“按意思找回内容”。如果只是偶尔找标题，普通搜索已经足够；如果你经常在任务、项目、里程碑、回顾和卡片之间来回找经验，本地语义搜索会更适合你。
