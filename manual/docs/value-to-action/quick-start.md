从方向到行动，不是先写一套宏大计划，而是先把一个真实输入放到合适位置。

## 一个真实场景

比如你想到“整理课程项目资料”，先放进收集箱，再判断它属于哪个项目，今天能做哪一步。

## 一条输入如何进入行动链路

![收集箱](../../screenshots/zh-cn/route-inbox-main.png)

收集箱先接住“整理课程项目资料”这样的临时想法。它还不一定是可执行任务，只是先别让这个输入丢掉。

![任务列表](../../screenshots/zh-cn/route-tasks-main.png)

当输入被整理成明确下一步，就应该来到任务列表。这里要能看出动作是什么、什么时候做，以及是否属于某个项目。

![项目页面](../../screenshots/zh-cn/route-projects-main.png)

项目页面承接更长时间的目标。如果一个想法不是一天能做完，而是会持续推进，就不要只把它留在任务列表里。

## 怎么判断下一步

| 你遇到的情况 | 先看什么 | 下一步 |
| --- | --- | --- |
| 不知道该从哪里开始 | 当前页面标题和主要入口 | 只选择和当前目标有关的一项 |
| 操作后结果不对 | 状态、空提示、访问记录或同步进度 | 回到上一层，按顺序排查 |
| 担心影响数据 | 备份、同步、账号或权限说明 | 先停下，确认范围后再继续 |

## 边界

开始时只需要一条真实任务。系统是在使用中长出来的。

## 下一步

读完这一节后，回到你正在处理的任务，只选一个最小动作继续：记录一条输入、检查一个状态、或打开相关设置完成一次确认。
