title: 本地語義搜尋與向量模型
description: "理解本地語意搜尋、模型下載、精度設定同多裝置協作。"
---

本地語義搜尋唔係要你多記一個搜尋技巧，而係將「搵同一個詞」改成「搵意思接近的任務、項目、里程碑、卡片同經驗」。當你喺 Granoflow 入面寫低好多記錄後，真正麻煩的地方通常唔係冇資料，而係唔記得當時用咗邊個詞。

向量搜尋就係為呢個場景準備。佢會喺本地將任務、項目、里程碑、卡片、回顧等內容轉成一組語意資訊。之後你新增卡片、搜尋舊記錄、匯入 AI 產生的卡片，Granoflow 就可以先搵出意思接近的內容，減少重複整理，亦為之後知識圖譜能力打基礎。

## 一個真實場景

你曾經寫過一張卡片：「唔好將收集箱當作長期清單。」幾星期後，你喺任務入面寫的是「臨時想法應該幾時清空」。普通搜尋可能更依賴「收集箱」「清單」呢啲字；啟用本地語義搜尋後，Granoflow 會嘗試將呢兩段話睇成同一類經驗，再將相關記錄排到前面。

呢度的重點唔係 AI 代你判斷邊張卡片一定正確，而係先縮細候選範圍。最後要關聯、跳過定新增，仍然由你決定。

## 佢會出現喺邊度

| 使用場景 | 啟用後會發生乜 | 關閉後會點 |
| --- | --- | --- |
| 任務詳情新增卡片 | 直接列出相似卡片，減少手動輸入關鍵詞 | 返到關鍵詞或舊的新增流程 |
| 搜尋頁和卡片管理頁 | 優先按語意接近程度排序 | 返到普通文字比對 |
| AI 匯入卡片 | 寫入前先展示可能重複或相關的卡片 | 不展示語意預覽 |
| 日、週、月複盤 | 推薦和當前複盤內容接近的卡片 | 只保留原有列表和入口 |
| 項目、里程碑、標籤候選 | 用語意接近度輔助排序 | 返到原有排序 |

## 模型資訊

第一次啟用本地語義搜尋時，Granoflow 會請你確認下載本地模型。模型唔會隨安裝包預裝；如果當前唔係 Wi-Fi，下載前會再次確認，並顯示需要下載的大小。

| 項目 | 內容 |
| --- | --- |
| 模型 | Google EmbeddingGemma Q8，本地設定 ID 為 `local_google_embeddinggemma_q8` |
| 模型來源 | Google EmbeddingGemma，使用 LiteRT / TFLite artifact，受 Gemma Terms of Use 約束 |
| 模型檔案 | `embeddinggemma-300M_seq512_mixed-precision.tflite`，約 179.1 MB |
| Tokenizer 檔案 | `sentencepiece.model`，約 4.7 MB |
| 下載和安裝佔用 | 約 183.8 MB，建議至少預留 300 MB 可用空間 |

::::note[下載後先啟用]
Granoflow 只有喺模型檔案下載完成並通過校驗後，先會啟用本地向量搜尋。校驗失敗時，模型唔會被載入。

向量搜尋係好強力的 AI 輔助功能，但唔係必裝組件。如果某部裝置空間緊張，可以先唔安裝，Granoflow 會繼續使用普通搜尋和舊流程。
::::

## 儲存精度同搜尋準確度

設定裡有兩個滑桿，名字相近，但作用唔同。先記住一個判斷：儲存精度決定記錄入面「保存咗幾多資訊」，搜尋準確度決定當前裝置「讀取幾多資訊來排序」。

| 設定 | 檔位 | 作用 |
| --- | --- | --- |
| 儲存精度 | 高 / 精細 / 最佳 | 決定每條記錄保存幾多向量資訊。記錄只保存到「高」時，將搜尋準確度調高都唔會補出不存在的資訊。 |
| 搜尋準確度 | 低 / 中 / 高 / 精細 / 最佳 | 決定當前裝置搜尋時讀取幾多向量資訊。記錄已經用「最佳」保存時，即使用較低搜尋準確度，仍然可以從高儲存精度中受益。 |

::::tip[多裝置用戶的簡單做法]
如果你有多台裝置，建議至少讓一台常用裝置保持「最佳」儲存精度。佢接觸到低精度記錄時，會喺背景將呢啲記錄升級到更高精度，呢個過程通常唔需要手動處理。
::::

## 模型檔案由你管理

已經下載的模型唔會因為你嘗試其他模型而自動刪除。Granoflow 會將刪除動作留畀你，因為有啲用戶會下載多個模型比較效果。

| 操作 | 規則 |
| --- | --- |
| 刪除已下載模型 | 由你喺設定裡主動刪除 |
| 刪除當前正在使用的模型 | 不允許直接刪除，避免誤刪後功能突然不可用 |
| 刪除最後一個模型 | 需要先關閉向量搜尋，再刪除模型 |

## 自動降級

Granoflow 會按裝置性能評估儲存精度、搜尋精度嘅預設值同可用上限；你可以喺設定裡自行調整。如果裝置壓力較高，Granoflow 可能會將已保存的設定降到更安全的位置。呢個降級會寫入真實設定，唔係只影響當前一次搜尋。

如果你一開始用較高搜尋精度好順暢，後來逐漸被降到較低檔，通常唔係模型壞咗，而係你嘅記錄變多咗。同樣嘅搜尋精度喺更大資料量上需要處理更多候選內容，佔用亦會增加；為咗避免搜尋拖慢裝置，Granoflow 會保存一個更穩妥嘅設定。

發生降級時，你會收到一條內部通知，入面會說明降級前係咩設定、降級後係咩設定。如果你認為裝置狀態已經恢復，可以再返到設定裡手動調高。

## 私隱同同步

向量來自你已經寫入 Granoflow 的文字內容。備份、匯入、同步和本地接口入面，向量欄位按文字欄位相同方式處理；唔同的是，向量欄位唔需要好似敏感文字咁做脫敏展示。

本地備份首版不主動匯出向量。匯入或同步後，Granoflow 會根據已有文字重新生成需要的向量。

## 邊界

「最佳」表示當前端側模型的最高本地檔位，不等於雲端 Gemini 等模型的能力上限。語意排序亦唔係最終判斷：如果你覺得某張卡片唔應該排喺前面，仍然以卡片內容、任務上下文同你自己的判斷為準。

如果你覺得查詢卡片的排序經常唔正確，可以到 GitHub issue 回饋。我哋會根據實際問題考慮用合適方式整合雲端向量 API。
