---

本機語意搜尋不是讓你多記一個搜尋技巧，而是把「找同一個詞」改成「找意思接近的任務、專案、里程碑、卡片和經驗」。當你在 Granoflow 裡寫下很多記錄後，真正麻煩的地方常常不是沒有資料，而是不記得當時用了哪個詞。

向量搜尋就是為這個場景準備的。它會在本機把任務、專案、里程碑、卡片、回顧等內容轉成一組語意資訊。以後你新增卡片、搜尋舊記錄、匯入 AI 產生的卡片，Granoflow 就能先找出意思相近的內容，減少重複整理，也為後續知識圖譜能力打基礎。

## 一個真實場景

你曾經寫過一張卡片：「不要把收集箱當作長期清單。」幾週後，你在任務裡寫的是「臨時想法應該什麼時候清空」。普通搜尋可能更依賴「收集箱」「清單」這些字；啟用本機語意搜尋後，Granoflow 會嘗試把這兩段話看成同一類經驗，再把相關記錄排到前面。

這裡的重點不是 AI 替你判斷哪張卡片一定正確，而是先把候選範圍縮小。最後要關聯、跳過還是新增，仍然由你決定。

## 它會出現在哪裡

| 使用場景 | 啟用後會發生什麼 | 關閉後會怎樣 |
| --- | --- | --- |
| 任務詳情新增卡片 | 直接列出相似卡片，減少手動輸入關鍵字 | 回到關鍵字或舊的新增流程 |
| 搜尋頁和卡片管理頁 | 優先按語意相近程度排序 | 回到普通文字比對 |
| AI 匯入卡片 | 寫入前先展示可能重複或相關的卡片 | 不展示語意預覽 |
| 日、週、月複盤 | 推薦和當前複盤內容相近的卡片 | 只保留原有列表和入口 |
| 專案、里程碑、標籤候選 | 用語意相近度輔助排序 | 回到原有排序 |

## 模型資訊

第一次啟用本機語意搜尋時，Granoflow 會請你確認下載本機模型。模型不會隨安裝包預裝；如果當前不是 Wi-Fi，下載前會再次確認，並顯示需要下載的大小。

| 項目 | 內容 |
| --- | --- |
| 模型 | Google EmbeddingGemma Q8，本機設定 ID 為 `local_google_embeddinggemma_q8` |
| 模型來源 | Google EmbeddingGemma，使用 LiteRT / TFLite artifact，受 Gemma Terms of Use 約束 |
| 模型檔案 | `embeddinggemma-300M_seq512_mixed-precision.tflite`，約 179.1 MB |
| Tokenizer 檔案 | `sentencepiece.model`，約 4.7 MB |
| 下載和安裝占用 | 約 183.8 MB，建議至少預留 300 MB 可用空間 |

::::note[下載後才啟用]
Granoflow 只有在模型檔案下載完成並通過校驗後，才會啟用本機向量搜尋。校驗失敗時，模型不會被載入。

向量搜尋是很強力的 AI 輔助功能，但不是必裝元件。如果某台裝置空間緊張，可以先不安裝，Granoflow 會繼續使用普通搜尋和舊流程。
::::

## 儲存精度和搜尋精度

設定裡有兩個滑桿，名字相近，但作用不同。先記住一個判斷：儲存精度決定記錄裡「保存了多少資訊」，搜尋精度決定當前裝置「讀取多少資訊來排序」。

| 設定 | 檔位 | 作用 |
| --- | --- | --- |
| 儲存精度 | 高 / 精細 / 最佳 | 決定每條記錄保存多少向量資訊。記錄只保存到「高」時，把搜尋精度調得更高也不會補出不存在的資訊。 |
| 搜尋精度 | 低 / 中 / 高 / 精細 / 最佳 | 決定當前裝置搜尋時讀取多少向量資訊。記錄已經用「最佳」保存時，即使用較低搜尋精度，仍然能從高儲存精度中受益。 |

::::tip[多裝置使用者的簡單做法]
如果你有多台裝置，建議至少讓一台常用裝置保持「最佳」儲存精度。它接觸到低精度記錄時，會在背景把這些記錄升級到更高精度，這個過程通常不需要手動處理。
::::

## 模型檔案由你管理

已經下載的模型不會因為你嘗試別的模型而自動刪除。Granoflow 會把刪除動作留給你，因為有些使用者會下載多個模型比較效果。

| 操作 | 規則 |
| --- | --- |
| 刪除已下載模型 | 由你在設定裡主動刪除 |
| 刪除當前正在使用的模型 | 不允許直接刪除，避免誤刪後功能突然不可用 |
| 刪除最後一個模型 | 需要先關閉向量搜尋，再刪除模型 |

## 自動降級

Granoflow 會依裝置性能評估儲存精度、搜尋精度的預設值與可用上限；你可以在設定裡自行調整。如果裝置壓力較高，Granoflow 可能會把已保存的設定降到更安全的位置。這個降級會寫入真實設定，不是只影響當前一次搜尋。

如果你一開始使用較高搜尋精度很順暢，後來逐漸被降到較低檔，通常不是模型壞了，而是你的記錄變多了。同樣的搜尋精度在更大的資料量上需要處理更多候選內容，佔用也會增加；為了避免搜尋拖慢裝置，Granoflow 會保存一個更穩妥的設定。

發生降級時，你會收到一條內部通知，裡面會說明降級前是什麼設定、降級後是什麼設定。如果你認為裝置狀態已經恢復，可以再回到設定裡手動調高。

## 隱私和同步

向量來自你已經寫入 Granoflow 的文字內容。備份、匯入、同步和本機接口裡，向量欄位按文字欄位相同的方式處理；不同的是，向量欄位不需要像敏感文字那樣做脫敏展示。

本機備份首版不主動匯出向量。匯入或同步後，Granoflow 會根據已有文字重新生成需要的向量。

## 邊界

「最佳」表示當前端側模型的最高本機檔位，不等於雲端 Gemini 等模型的能力上限。語意排序也不是最終判斷：如果你覺得某張卡片不該排在前面，仍然以卡片內容、任務上下文和你的判斷為準。

如果你覺得查詢卡片的排序經常不正確，可以到 GitHub issue 回饋。我們會根據實際問題考慮用合適方式整合雲端向量 API。
