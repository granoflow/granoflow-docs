專案說明任務屬於哪個目標，標籤說明任務有什麼共同特徵。比如「健身 App 開發」是專案；「等待回覆」「低精力」「設計稿」這類跨專案都會出現的狀態或類型，更適合做標籤。

標籤不是越多越好。它的價值在於篩選時真的能幫你縮小範圍。

## 標籤管理適合做什麼

![標籤管理頁面](../../screenshots/zh-tw/route-custom-tags-management-settings-custom-tags-main.png)

標籤管理頁面適合處理全域標籤：新增、編輯、刪除，或為自訂標籤設定範本。圖裡要注意的是列表關係：標籤不是某一條任務的私有欄位，而是可以被多條任務複用的分類。

如果你只是給當前任務加上一個已有標籤，在任務詳情裡操作就夠了；如果要整理標籤名稱、範本或刪除標籤，再進入標籤管理。

## 標籤適合記什麼

| 用途 | 標籤範例 | 為什麼適合 |
| --- | --- | --- |
| 精力或場景 | `低精力`、`深度工作`、`零碎時間` | 幫你按當前狀態挑任務 |
| 等待狀態 | `等待他人`、`待確認` | 跨專案追蹤卡住的事 |
| 任務類型 | `電話`、`寫作`、`設計` | 方便批次處理同類動作 |
| 臨時重點 | `本週重點`、`稍後處理` | 短期篩選，不必建專案 |

不建議把專案名稱複製成標籤。任務已經屬於專案時，再加同名標籤通常只會讓分類變亂。

## 自訂標籤範本

自訂標籤可以帶描述範本與節點範本。之後任務選擇這個標籤時，如果任務還沒有描述和節點，GranoFlow 會把範本內容複製到這條任務自己的描述與節點裡。

範本是一次性複製。複製後，內容就屬於任務本身；以後修改或刪除標籤範本，不會自動改寫已經建立過的任務。

| 標籤範例 | 範本適合放什麼 |
| --- | --- |
| `account` | 平台名稱、網址、信箱、手機、第三方登入與備註 |
| `bug` | 重現步驟、預期結果、實際結果 |
| `feature` | 使用者價值、使用場景、驗收標準 |

如果任務已經有描述或節點，範本會跳過，避免覆蓋已有內容。

## 刪除標籤的影響

刪除標籤不會刪除任務。它只會把這個標籤從使用它的任務上移除。

::::caution[刪除前先確認]
刪除標籤是不可撤銷的。確認這個分類不再需要，再刪除。
::::

## 標籤多了怎麼辦

標籤太多時，篩選會變得跟不篩選差不多。可以定期做三件事：

- 合併意思接近的標籤
- 刪除已經不用的標籤
- 把專案名從標籤裡移出去，交給專案管理
